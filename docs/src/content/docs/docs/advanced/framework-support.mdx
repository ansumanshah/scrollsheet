## Compatibility table

<div className="table-scroll">

| Framework | Setup | Notes |
| --- | --- | --- |
| Next.js App Router | Yes, with `'use client'` | See the caveat below: the file that renders `<Sheet.Root>` needs the directive too, not just scrollsheet's own. |
| Next.js Pages Router | Yes | No RSC boundary; `"use client"` has no effect. |
| Remix / React Router v7 | Yes | Uses scrollsheet's SSR and hydration behavior. |
| Astro | Yes | See the caveat below. |
| Vite (SPA, no SSR) | Yes | No server render or hydration setup needed. |

</div>

<Aside type="caution" title="Next.js App Router">
  `Sheet.Root`, `Sheet.Trigger`, and the other components use state, event handlers, and DOM
  refs. They require a Client Component. scrollsheet's own `"use client"` banner on every
  dist chunk is not enough by itself: a Server Component that imports `Sheet` and renders
  `<Sheet.Root>` gets one opaque client reference for the whole `Sheet` object, so `Sheet.Root`
  cannot be used that way. When using the `Sheet.*` namespace, add `'use client'` to the
  wrapper component's file.
</Aside>

<Aside type="caution" title="Astro caveat">
  An island only hydrates if you give it a `client:*` directive (`client:load`, `client:idle`,
  `client:visible`, etc.). Add one to the component that renders your `Sheet.Trigger`. Mount
  behavior is the same for each directive.
</Aside>
