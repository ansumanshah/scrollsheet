handle, and close-button visuals. Import it once next to your components. `Sheet.Content`'s
`className` lands on the panel.

## Zero-config entry

To inject styles at runtime instead of importing CSS, use `scrollsheet/auto`:
the same components with the stylesheet embedded, injected the first time a sheet opens. Sheets
only render after JS runs, and the stylesheet is injected before the sheet is opened.

```tsx
import { Sheet } from "scrollsheet/auto";
```

The embed costs {BUNDLE_SIZES.auto.gzipKb.toFixed(1)} kB gzip for `Sheet` against the default
entry's {BUNDLE_SIZES.index.gzipKb.toFixed(1)}. Toasts on the default entry need `scrollsheet/toast.css`; add `scrollsheet/styles.css`
when the app also uses sheets or dialogs. Use one entry consistently to avoid duplicate
component code and separate state instances.

Every number above is measured on a production build. Dev-only warning strings sit behind a
development/production export condition, the same one Vite, webpack 5+, and Next.js all set
automatically. Supported bundlers select a build without those warnings for production.
Bundlers that omit the development condition also use the production build during development.

The `themeColorDimming` controller is a separate chunk, fetched when the prop is enabled.

<Aside type="tip">
  For CSP with the `auto` entry, pass `nonce` to `Sheet.Root`. Shadow DOM injection
  (`injectStylesInto`) also needs the `auto` entry; the default entry has no stylesheet to
  inject.
</Aside>

## Dark mode

Light is the default palette everywhere. An app with no theming of its own never flips dark just
because the visitor's OS is set to dark: the panel, handle, and close button all keep their
light-mode colors regardless of `prefers-color-scheme`.

Opt into dark by setting `data-scrollsheet-theme="dark"` on an ancestor, typically `<html>`:

```html
<html data-scrollsheet-theme="dark">
```

To make the panel track the OS scheme automatically, use `"system"` instead:

```html
<html data-scrollsheet-theme="system">
```

Any other value, or no attribute at all, renders light. The attribute is page-level: any
ancestor carrying it switches the built-in defaults, and a nested
`data-scrollsheet-theme="light"` does not switch a subtree back. To theme one sheet differently
from the rest of the page, set the tokens on that sheet instead.

Your own `--scrollsheet-bg`, `--scrollsheet-fg`, `--scrollsheet-handle`,
`--scrollsheet-handle-hover`, `--scrollsheet-close-bg`, `--scrollsheet-close-color`,
`--scrollsheet-close-bg-hover`, and `--scrollsheet-close-color-hover` overrides win in every
mode: the attribute only changes which built-in fallback color those variables fall back to.

## Toast styling

`Toaster` renders each card as `.scrollsheet-toast` (icon: `.scrollsheet-toast-icon`, body:
`.scrollsheet-toast-body`, title: `.scrollsheet-toast-title`, description:
`.scrollsheet-toast-description`, actions: `.scrollsheet-toast-action` /
`.scrollsheet-toast-cancel` / `.scrollsheet-toast-close`) and reads its layout knobs from
`--scrollsheet-toast-*` custom properties: `--scrollsheet-toast-gap`,
`--scrollsheet-toast-offset`, `--scrollsheet-toast-mobile-offset`. Override either the same way
you'd style any card:

```css
.scrollsheet-toast {
  border-radius: 12px;
}
```

## Sonner compatibility

Arrived with an existing Sonner integration? Its `import { toast, Toaster } from 'scrollsheet'`
compat layer stamps corresponding `sonner-*` classes and `data-sonner-*` attributes on supported
slots. Check existing selectors against the rendered markup. See
[Migrate from Sonner](/docs/migrating/from-sonner). Starting fresh, with no Sonner CSS to keep
matching? `<Toaster sonnerCompat={false}>` drops the mirrored names and renders the neutral
`.scrollsheet-*` classes and attributes only.
